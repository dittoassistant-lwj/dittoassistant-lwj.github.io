Most important paper of the day

SAC: Disaggregated KV Cache System for Sparse Attention LLMs with CXL

Authors & affiliations: Ruiyang Ma, Teng Ma, Junru Li, Hantian Zha, Xuchun Shang, Qingda Hu, Zheng Liu, Xinjun Yang, Tao Ma, and Guojie Luo. Affiliations: Peking University; Alibaba Cloud; Renmin University of China.

Tags: Disaggregated LLM Serving, CXL Memory, KV Cache

Why this is the top pick: This is the strongest network/infrastructure signal today because it is a clean RDMA-versus-CXL data-path argument for LLM serving. The paper is not just saying “use disaggregation”; it shows that the access granularity of the model changes which fabric primitive is appropriate.

Deeper explanation: SAC matters because sparse attention breaks the default assumption behind RDMA-style disaggregated KV serving. If only a few KV entries are needed per layer, fetching an entire prefix is not just wasteful; it turns the interconnect into a pre-decode bottleneck and burns local memory that should be used for concurrency. The CXL argument is architectural: fine-grained load/store access can match sparse runtime lookup better than a bulk-transfer NIC path.

  • Problem: RDMA-based disaggregated KV systems usually prefetch the full prefix KV cache into local memory before decode. That matches dense attention, but it wastes bandwidth and memory for sparse attention models where only top-k KV entries are active at each layer.
  • Key contributions: Proposes SAC, a disaggregated KV cache system for sparse-attention LLMs that uses CXL load/store semantics to fetch only required top-k KV entries on demand.; Frames RDMA full-prefix prefetch as both a transmission bottleneck and a local-memory waste problem for emerging sparse attention models such as DeepSeek-style sparse attention.; Evaluates on DeepSeek-V3.2 with SGLang, reporting 2.1× higher throughput, 9.7× lower TTFT, and 1.8× lower TBT than RDMA-based baselines, with only 9% throughput loss versus a non-disaggregated upper bound.
  • Why it matters architecturally: It points to backend selection by access pattern: RDMA for coarse transfers, CXL-style memory semantics for sparse fine-grained cache reads.
  • Useful diagram: Figure 2 is the useful architecture comparison: it contrasts RDMA-based memory pools with CXL-based memory pools and makes the data-path difference explicit. Figure 1 also helps by showing how DeepSeek Sparse Attention produces runtime top-k KV lookups.
Fresh arXiv CS paper · CXL memory pooling / sparse-attention KV cache / disaggregated serving

SAC: Disaggregated KV Cache System for Sparse Attention LLMs with CXL

Authors & affiliations: Ruiyang Ma, Teng Ma, Junru Li, Hantian Zha, Xuchun Shang, Qingda Hu, Zheng Liu, Xinjun Yang, Tao Ma, and Guojie Luo. Affiliations: Peking University; Alibaba Cloud; Renmin University of China.

Tags: Disaggregated LLM Serving, CXL Memory, KV Cache

Problem: RDMA-based disaggregated KV systems usually prefetch the full prefix KV cache into local memory before decode. That matches dense attention, but it wastes bandwidth and memory for sparse attention models where only top-k KV entries are active at each layer.

Key contributions from the authors:

  • Proposes SAC, a disaggregated KV cache system for sparse-attention LLMs that uses CXL load/store semantics to fetch only required top-k KV entries on demand.
  • Frames RDMA full-prefix prefetch as both a transmission bottleneck and a local-memory waste problem for emerging sparse attention models such as DeepSeek-style sparse attention.
  • Evaluates on DeepSeek-V3.2 with SGLang, reporting 2.1× higher throughput, 9.7× lower TTFT, and 1.8× lower TBT than RDMA-based baselines, with only 9% throughput loss versus a non-disaggregated upper bound.

Why it matters: This is the strongest network/infrastructure signal today because it is a clean RDMA-versus-CXL data-path argument for LLM serving. The paper is not just saying “use disaggregation”; it shows that the access granularity of the model changes which fabric primitive is appropriate.

Key insights:

  • Sparse attention changes the serving bottleneck from full-cache movement to fine-grained, latency-sensitive KV lookup; a bulk-transfer fabric can become the wrong abstraction.
  • CXL’s cache-line load/store model is valuable precisely where RDMA gather/scatter and CPU-orchestrated remote reads become too expensive.
  • For long-context sparse attention, keeping the full KV cache remote and pulling only active entries can simultaneously reduce network bytes and local DRAM footprint.
  • The result suggests future serving systems should select disaggregation backends based on model access pattern, not just raw bandwidth or deployment convenience.

Actionable lessons: For KV-cache architecture, do not treat RDMA memory pools and CXL memory pools as interchangeable capacity tiers. Profile the cache access granularity: dense contiguous reuse favors bulk movement, while sparse top-k access favors low-latency load/store semantics and page/cache-line-aware placement.

Fresh arXiv CS paper · 10,000-GPU observability / fail-slow diagnosis / training traces

ARGUS: Production-Scale Tracing and Performance Diagnosis for over 10,000-GPU Clusters

Authors & affiliations: Jiasheng Zhou, Longbin Zeng, Clavis Chen, Ruiming Lu, Qinwei Yang, Leyi Ye, Ray Ying, and Key Zhang. Affiliations: Tencent.

Tags: AI Cluster Observability, GPU Training, Reliability

Problem: Large LLM training clusters need always-on fine-grained observability, but full profilers create too much overhead and trace volume. Coarse resource monitors miss root causes such as link degradation, masked compute stragglers, or kernel-level stalls.

Key contributions from the authors:

  • Designs an always-on tracing system for 10,000+ GPU training clusters, decomposing observation into CPU call stacks, framework semantics, and GPU kernel execution with less than 2% overhead.
  • Builds a real-time transport, tiered-storage, and online-analysis pipeline; kernel traces are statistically compressed by roughly 3,700×, from 10 MB to 2.7 KB per rank per step.
  • Uses progressive diagnosis to narrow anomalies from iteration-level symptoms to cross-rank attribution and kernel-level suspects, validated by six months of deployment and real cases including communication link degradation.

Why it matters: For superpod work, this paper is very close to production reality: the hard problem is not merely detecting that a step is slow, but attributing the slowdown across thousands of ranks when compute and communication symptoms mask each other.

Key insights:

  • The paper’s 4096-GPU fail-slow example reports iteration spikes wasting about 23,758 GPU-hours, a reminder that “small” intermittent degradations become huge at cluster scale.
  • Cross-rank comparison only becomes practical after aggressive semantic compression; raw kernel traces are too large for continuous online diagnosis.
  • ARGUS treats the training iteration hierarchy as the diagnostic scaffold, moving from iteration time to phase attribution to kernel distributions.
  • The case studies explicitly include link degradation and compute stragglers hidden behind communication symptoms, which is the kind of ambiguity that fabric telemetry alone often cannot resolve.

Actionable lessons: For production cluster observability, keep network/fabric counters tied to training semantics. A useful diagnosis path should correlate rank, phase, collective/compute boundary, and kernel distribution, otherwise fail-slow nodes and degraded links blur together.

Fresh arXiv CS paper · multi-GPU serving / session migration / NCCL-based state movement

TurboServe: Serving Streaming Video Generation Efficiently and Economically

Authors & affiliations: Youhe Jiang, Haoxu Wang, Haotong Bao, Kai Jiang, Jianfei Chen, Jun Zhu, Fangcheng Fu, and Jintao Zhang. Affiliations: Shanghai Jiao Tong University; Shengshu Technology; Tsinghua University.

Tags: AI Serving, GPU Scheduling, State Migration

Problem: Streaming video generation creates long-lived sessions with state that must survive active and idle periods. Static placement and provisioning become poor matches when session duration and active-session count fluctuate over time.

Key contributions from the authors:

  • Formulates streaming video generation as an online scheduling problem that jointly chooses session placement and GPU provisioning under per-chunk latency constraints.
  • Implements coalesced chunk processing, GPU-CPU offload for idle-session suspension/resumption, and NCCL-based GPU-GPU migration for online rebalancing.
  • Evaluates on Shengshu Technology production traces and clusters up to 64 NVIDIA B300 GPUs, reporting 37.5% lower worst-case per-chunk latency and 37.2% lower GPU operating cost on average.

Why it matters: This is not classic LLM networking, but it is a good serving-systems signal because the control loop is state movement aware. The moment sessions become long-lived, scheduling becomes a fabric and memory-placement problem, not just a queueing problem.

Key insights:

  • Long-lived generative sessions make placement decisions decay over time; a good placement at session start can become a bottleneck minutes later.
  • NCCL-based GPU-GPU migration is the network-facing mechanism that lets the scheduler correct imbalance without killing session state.
  • GPU-CPU offload is used as a suspension primitive, freeing GPU memory during idle windows while preserving resumability.
  • The paper’s framing generalizes to agentic LLM serving: active/idle phases, state mobility, and per-step latency SLOs all matter.

Actionable lessons: When designing serving control planes for stateful generative workloads, measure the cost of moving state, not only the cost of running kernels. The scheduler should know when migration bytes, offload latency, and GPU memory pressure dominate the per-request critical path.

Fresh arXiv CS paper · remote memory / RDMA and TCP memory tiers / transfer-round-aware operators

REMOP: REmote-Memory-aware OPerator Optimization

Authors & affiliations: Shiquan Zhang, Yunhao Mao, Yuqiu Zhang, Gengrui Zhang, Jeyhun Karimov, and Hans-Arno Jacobsen. Affiliations: University of Toronto; Confluent Inc.; Concordia University; Microsoft Corporation.

Tags: Disaggregated Memory, RDMA, Data Systems

Problem: Remote and disaggregated memory tiers change out-of-memory execution cost. Disk-oriented operator policies minimize bytes, but remote memory adds a fixed network/protocol round-trip per transfer, so too many transfer rounds can dominate latency.

Key contributions from the authors:

  • Introduces a remote-memory cost model that accounts for both data volume and transfer rounds, plus an operator abstraction for tuning buffer partitions.
  • Derives transfer-round-aware policies for blocked nested-loop join, external merge sort, and external hash join, implemented as optimized DuckDB operator variants.
  • Evaluates over TCP-based REMON and RDMA-based Infiniswap, reporting up to 97% fewer transfer rounds, up to 48% lower operator runtime, and 22.7%/26.4% average speedups on spilling TPC-H/TPC-DS queries.

Why it matters: The paper is valuable because it names a general design trap in disaggregated infrastructure: optimizing for bytes alone is wrong when every remote-memory access also pays a fabric/protocol RTT.

Key insights:

  • Remote memory can have more bandwidth than SSD yet still be worse for fine-grained spilling if transfer rounds explode.
  • The right batching/allocation policy may intentionally move slightly more bytes to reduce round trips, reversing a classic disk-era heuristic.
  • The evaluation covers both TCP and RDMA-backed memory tiers, which makes the lesson less tied to one implementation.
  • The same “rounds versus bytes” trade-off appears in KV cache movement, checkpoint streaming, and remote tensor/prefix fetching.

Actionable lessons: For disaggregated memory systems, expose transfer-round count as a first-class metric next to bandwidth and bytes. Operator/runtime policies should batch remote accesses around RTT amortization, especially when the workload spills many small objects or pages.

Fast take

Read SAC first for the CXL-versus-RDMA KV-cache design point. ARGUS is the production superpod observability paper. TurboServe is useful for state migration in long-lived generative sessions. REMOP is the disaggregated-memory paper with the cleanest “RTT rounds matter” lesson.
