Most important paper of the day

Co-Fabric: Breaking Host-Domain Boundaries for Unified xPU Interconnection

Authors & affiliations: Zhen Peng, Jiaming Huang, Chaofan Chen, Zhao Zhang, An Wu, Baoyang Liu, Xinglong Wang, Tanlong Ci, Jinfeng Li, Xueke Duan, Hao Wang, Xi Chen, Shunshun Zhang, Zhiyuan Su, Zhu Cao, Zhichong Dou, Shaohua Wu, Lu Jing, and Yue Yuan — IEIT SYSTEMS Co., Ltd., Beijing, China; IEIT SYSTEMS Co., Ltd., JiNan, China.

Tags: Scale-up Networking, xPU Interconnects, AI Superpods

Why this is the top pick: This is the strongest Ethan-signal today: it is directly about the scale-up fabric boundary between “network” and “bus,” and it attacks the same pain point as NVLink/NVL-style supernodes or CloudMatrix-like domains — how to make many accelerators behave like one memory-semantic pool without paying Ethernet-shaped overhead everywhere.

Deeper explanation: Co-Fabric is interesting because it explicitly challenges the default habit of stretching host-centric Ethernet/RDMA semantics into the scale-up domain. The paper’s core bet is that accelerator pods need a fabric that looks more like a unified device/memory substrate than a collection of hosts exchanging packets. Whether or not the exact Co-Fabric design wins, the framing is right: superpod efficiency depends on protocol semantics, address-space construction, and hardware routing as much as raw SerDes bandwidth.

  • Problem: Large models increasingly shard parameters across xPUs and host domains, making xPU-to-xPU communication a first-order efficiency limiter. Ethernet/RoCE-based network approaches bring protocol-stack and fragmented-addressing overheads, while conventional bus-like fabrics tend to stay inside one host domain.
  • Key contributions:
  • Proposes Co-Fabric, a bus-based scale-up interconnect that breaks host-domain boundaries while preserving unified addressing and memory-semantic access across xPUs.
  • Defines a streamlined four-layer protocol stack with native reliability, Port-ID-based routing, shadow-device auto-enumeration, and cross-domain P2P mechanisms.
  • Evaluates a 64-xPU 3D-mesh system, reporting over 50% lower inter-node latency, 2–5× higher bandwidth than a RoCE-based scaling system, and 30%–80% DeepSeek R1 inference throughput improvement.
  • Why it matters architecturally: It points toward a clean separation between scale-up memory-semantic fabrics and scale-out datacenter transports — a distinction that matters for NVL-like domains, heterogeneous xPU clusters, and model-sharded inference.

Co-Fabric: Breaking Host-Domain Boundaries for Unified xPU Interconnection

Authors & affiliations: Zhen Peng, Jiaming Huang, Chaofan Chen, Zhao Zhang, An Wu, Baoyang Liu, Xinglong Wang, Tanlong Ci, Jinfeng Li, Xueke Duan, Hao Wang, Xi Chen, Shunshun Zhang, Zhiyuan Su, Zhu Cao, Zhichong Dou, Shaohua Wu, Lu Jing, and Yue Yuan — IEIT SYSTEMS Co., Ltd., Beijing, China; IEIT SYSTEMS Co., Ltd., JiNan, China.

Tags: Scale-up Networking, xPU Interconnects, AI Superpods

Problem: Large models increasingly shard parameters across xPUs and host domains, making xPU-to-xPU communication a first-order efficiency limiter. Ethernet/RoCE-based network approaches bring protocol-stack and fragmented-addressing overheads, while conventional bus-like fabrics tend to stay inside one host domain.

Key contributions from the authors:

  • Proposes Co-Fabric, a bus-based scale-up interconnect that breaks host-domain boundaries while preserving unified addressing and memory-semantic access across xPUs.
  • Defines a streamlined four-layer protocol stack with native reliability, Port-ID-based routing, shadow-device auto-enumeration, and cross-domain P2P mechanisms.
  • Evaluates a 64-xPU 3D-mesh system, reporting over 50% lower inter-node latency, 2–5× higher bandwidth than a RoCE-based scaling system, and 30%–80% DeepSeek R1 inference throughput improvement.

Why it matters: This is the strongest Ethan-signal today: it is directly about the scale-up fabric boundary between “network” and “bus,” and it attacks the same pain point as NVLink/NVL-style supernodes or CloudMatrix-like domains — how to make many accelerators behave like one memory-semantic pool without paying Ethernet-shaped overhead everywhere.

Key insights:

  • The key architectural move is to stop treating cross-host xPU traffic as ordinary host-network-host messaging; Co-Fabric pushes routing and addressing closer to device-level fabric semantics.
  • Shadow-device enumeration is the bridge between software discoverability and unified memory semantics: each host can see remote xPUs through local abstractions while packet routing uses fabric Port IDs.
  • The paper’s comparison with RoCE is less about “Ethernet bad” and more about workload semantics: model-sharded inference wants low-latency, fine-grained device access, not only high bisection bandwidth.
  • The cost/power claims are notable because protocol simplification is framed as an interconnect economics lever, not just a latency optimization.

Actionable lessons: For superpod architecture, separate the scale-up problem from the scale-out transport problem. If the workload expects memory-semantic xPU access, model the address space, enumeration path, reliability mechanism, and routing header as first-class design surfaces rather than layering everything onto host-centric RDMA abstractions.

WeightBridge: An Efficient Weight Transfer Library for Reinforcement Learning

Authors & affiliations: Xuanlin Jiang, Samuel Hsia, Michael Kuchnik, Zachary DeVito, Minlan Yu, and Carole-Jean Wu — FAIR at Meta; Harvard University.

Tags: Distributed RL, Weight Transfer, RDMA/AI Data Movement

Problem: RL post-training alternates between trainers and rollout generators, so updated model weights must be redistributed frequently. As MoE parameter counts grow and GPU compute improves faster than inter-node RDMA bandwidth, weight transfer becomes a real stall source rather than background plumbing.

Key contributions from the authors:

  • Introduces WeightBridge, a general weight-transfer library that automatically discovers element-wise correspondence between heterogeneous trainer and rollout layouts.
  • Plans redundancy-free, load-balanced many-to-many transfers across different parallelization layouts, replication factors, tensor formats, and synchronization modes.
  • Reports up to 42× lower average GPU stall time than a state-of-the-art open-source RL framework, plus successful integration into multiple RL stacks through a small API.

Why it matters: This paper is a clean reminder that AI training infrastructure is gaining new “collective-adjacent” data paths. Weight movement between training and inference engines is not all-reduce, but it has the same fabric-facing properties: layout transforms, replication, synchronization, and network saturation all matter.

Key insights:

  • The hard part is not merely bandwidth; it is semantic mismatch between trainer and rollout layouts — tensor parallelism, packing, transposition, quantization, and replication all change the transfer graph.
  • Avoiding redundant traffic is central once rollout replicas multiply; naïve broadcast-like paths can burn fabric bandwidth and stall GPUs even when each individual copy looks simple.
  • Synchronization mode is part of the data-plane contract: stale-tolerant asynchronous RL and strict synchronous RL need different coordination without rewriting the framework.
  • The paper’s production observation — GPUs stalled on weight transfer for up to 27% of execution time — is a useful smell test for post-training clusters.

Actionable lessons: Treat trainer-to-rollout weight propagation as a schedulable communication primitive. Capture tensor layout metadata explicitly, plan transfers globally across replicas, and expose stall-time/fabric-utilization telemetry rather than hiding weight sync inside RL framework glue.

verified arXiv paper · Photonic Interconnects, Circuit Scheduling, Collectives

Tetris: Circuit Scheduling for Rearrangeably Non-Blocking Photonic Interconnects

Authors & affiliations: Eliezer Amponsah, Deeksha P Rao, and Vamsi Addanki — Purdue University.

Tags: Photonic Interconnects, Circuit Scheduling, Collectives

Problem: Reconfigurable photonic fabrics can provide high-bandwidth optical circuits, but practical rearrangeably non-blocking designs use internal 2×2 switch networks. Establishing a new circuit can reroute existing circuits and impose reconfiguration delay on traffic that was otherwise unrelated.

Key contributions from the authors:

  • Defines the scheduling problem for rearrangeably non-blocking photonic interconnects, where route changes inside the fabric matter as much as endpoint matching.
  • Introduces Tetris, which prioritizes bottleneck endpoints, accounts for remaining communication plus reconfiguration work, and preserves ongoing connections where possible.
  • Shows simulation and hardware-emulation results with up to 6.6× lower All-to-All completion time than Birkhoff–von Neumann-based scheduling and about 30% improvement over Sunflow.

Why it matters: This is highly relevant to AI cluster fabrics because MoE and collectives are full of all-to-all-ish demand matrices. The important bit is not just “photonic is fast”; it is that the scheduler must understand partial reconfiguration cost and internal fabric state, otherwise the optical fabric can self-inflict latency.

Key insights:

  • RNB photonic fabrics violate the usual clean abstraction that a matching is just a matching; the internal route can force unrelated connections to move.
  • All-to-All matrices from model workloads are often not doubly stochastic, so endpoint bottlenecks dominate completion time and should drive scheduling priority.
  • Reconfiguration delay changes the optimal next circuit; preserving existing circuits can beat repeatedly chasing the heaviest matching.
  • The paper hints at future multi-tenant problems: partial reconfiguration and internal-route interference create a new resource-allocation surface inside the fabric.

Actionable lessons: For optical/reconfigurable AI fabrics, evaluate schedulers with realistic collective and MoE traffic matrices, not only idealized doubly stochastic demands. The control plane should track internal route churn and charge reconfiguration delay to scheduling decisions.

verified arXiv paper · RDMA over WAN, FPGA SmartNICs, AI Factory Scale-across

Scalable Packet Tracking on FPGAs for Erasure-Coded RDMA over Lossy WANs

Authors & affiliations: Yicheng Qian, Konstantin Taranov, Yevgeny Yankilevich, Assaf Shacham, Mahmoud Elhaddad, Abdul Kabbani, Miriam Leeser, and Nadeen Gebara — Northeastern University, USA; Microsoft Corporation, USA.

Tags: RDMA over WAN, FPGA SmartNICs, AI Factory Scale-across

Problem: Scale-across AI systems that connect multiple datacenters cannot assume lossless, low-RTT datacenter fabrics. RDMA over lossy WANs faces packet loss, path diversity, reordering, and huge BDPs; erasure coding can help, but only if packet-arrival tracking is fast and scalable in NIC hardware.

Key contributions from the authors:

  • Presents COMET, a fully hardware-offloaded packet-arrival tracking design for multi-path, erasure-coded RDMA on FPGA-based NICs.
  • Uses a scalable cache-based architecture that decouples on-chip memory footprint from link bandwidth-delay product.
  • Reports line-rate operation at 400 Gbps and beyond, with capacity for 6× more concurrent connections than state-of-the-art SoC-based designs and scalability toward 1.6 Tbps NICs.

Why it matters: This one matters because it addresses the ugly underlay of geo-distributed or power-constrained “AI factory” scaling. If training spans sites, the network stops looking like a lossless Clos and starts looking like a high-BDP, lossy, multipath transport problem — exactly where NIC-offloaded recovery state becomes decisive.

Key insights:

  • The paper targets packet-arrival tracking, a small but critical mechanism: erasure-coded recovery needs precise knowledge of which symbols arrived without spending BDP-proportional SRAM per connection.
  • Moving this state machine onto FPGA NIC logic avoids host involvement on the recovery critical path and keeps up with multi-hundred-Gbps rates.
  • The design explicitly assumes multipath and jitter, which is the right model for WAN-scale AI rather than pretending RDMA can simply stretch across regions.
  • Connection-state scaling is the central constraint; high link speed without enough concurrent tracked flows would not be useful for real AI traffic mixes.

Actionable lessons: For cross-region AI fabrics, design transport recovery around high BDP and loss from day one. Budget NIC SRAM/state carefully, prefer hardware-offloaded fast paths for arrival tracking, and benchmark with multipath reordering plus jitter rather than clean single-path traces.

verified arXiv paper · MoE Inference, Compute/Communication Overlap, GPU Scheduling

Weave: Fine-Grained Dynamic SM Scheduling in an MoE Megakernel for Compute-Communication Overlap

Authors & affiliations: Ziyu Huang, Yangjie Zhou, Chenhao Zhu, Zihan Liu, Jinyu Liu, Shulai Zhang, Xingxun Tang, Hongzhe Yan, Xinhao Luo, Minyi Guo, Xiu Lin, Yinghao Yu, Guodong Yang, Liping Zhang, Shixuan Sun, and Jingwen Leng — Shanghai Jiao Tong University; National University of Singapore; Alibaba Group.

Tags: MoE Inference, Compute/Communication Overlap, GPU Scheduling

Problem: Expert-parallel MoE inference turns dispatch and combine into distributed communication phases. Existing overlap systems often use fixed SM partitions or coarse policies, but the right communication/computation split varies by layer, GPU, routing result, and sequence shape.

Key contributions from the authors:

  • Introduces Weave, a MoE overlap system that dynamically chooses per-layer and per-GPU SM allocation for communication and computation inside a persistent megakernel.
  • Uses routing results and a lightweight cost model to drive spatial SM partitioning and temporal coordination between communication and computation workers.
  • Evaluates six MoE models on 4×H100 SXM GPUs, reporting a 2.89× geometric-mean MoE-layer speedup and 1.33× end-to-end speedup over five baselines.

Why it matters: This is a close-to-the-metal systems paper for MoE serving. It shows that “overlap communication with compute” is no longer a binary feature; the runtime needs fine-grained resource control because NVLink bandwidth, token routing, and GEMM throughput shift from layer to layer.

Key insights:

  • Routing results are runtime metadata that should feed scheduling immediately; static SM splits leave either communication workers or compute workers underutilized.
  • The compute/interconnect gap is widening, so exposed dispatch/combine cost can dominate even when kernels are individually optimized.
  • Persistent megakernels can become mini-runtimes, making scheduling decisions inside the GPU execution envelope instead of bouncing control to the host.
  • The spatial and temporal schedulers solve different waste modes: wrong SM ratios versus bubbles from MoE dependencies.

Actionable lessons: When building MoE inference runtimes, expose routing volume, per-GPU communication demand, and link bandwidth to the kernel scheduler. Avoid fixed SM reservations for communication unless workload variance is low; measure overlap quality via both link utilization and SM idleness.
