AI cluster networking & infrastructure brief

Today’s batch is very much in the “agentic serving becomes infrastructure” lane: KV cache starts behaving like a distributed data plane, agent coordination shapes backend traffic, and the NIC/DPU/NoC papers are useful reminders that offload and reliability only matter when the protocol boundary is clean.

Most important paper of the day

TokenCake: A KV-Cache-centric Serving Framework for LLM-based Multi-Agent Applications

Authors & affiliations: Zhuohang Bian, Feiyang Wu, Zhuoran Li, Teng Ma, and Youwei Zhuo. Affiliations: Peking University, Beijing, China; Alibaba Group, Beijing, China.

Tags: LLM Serving, KV Cache Movement, Agentic AI Infrastructure

Why this is the top pick: This is the strongest signal today because it treats KV cache as a movable, schedulable resource with workflow semantics. That is exactly where disaggregated/agentic serving becomes a network-and-memory problem instead of just a batching problem.

Deeper explanation: TokenCake is the paper I would read first because it makes the serving layer aware of the agent workflow that created the load. In single-request serving, KV cache is mostly a per-session HBM residency problem. In multi-agent serving, the cache has a lifecycle: some agents are idle behind tool calls, some are on the critical path, and some will resume soon enough that prefetching their KV state can hide movement. That turns cache placement into a scheduling and data-movement problem. For Ethan’s world, the interesting part is the implied contract between application DAG, serving runtime, and fabric: once KV cache is offloaded or migrated, PCIe/NVLink/NIC bandwidth and prediction accuracy become part of tail latency.

  • Problem: Multi-agent LLM applications create KV-cache pressure that is different from single-session serving: agents block on tool calls while holding GPU memory, while critical-path agents can lose cache residency because other agents contend for the same memory pool.
  • Key contributions: Introduces TokenCake, an agent-aware serving framework that co-optimizes scheduling and KV-cache memory management rather than treating each request independently.; Adds a Temporal Scheduler that offloads idle KV caches during function calls and predictively uploads them before the agent needs to resume, hiding transfer latency where possible.; Adds a Spatial Scheduler that dynamically partitions GPU memory using both workflow graph structure and runtime state to protect critical-path agents; reports more than 47.06% end-to-end latency reduction and up to 16.9% higher effective GPU-memory utilization over vLLM on representative multi-agent benchmarks.
  • Why it matters architecturally: Expose workflow DAGs and tool-call state to the serving layer. For large agentic deployments, treat KV cache migration like a first-class data plane: budget transfer bandwidth, preserve critical-path cache residency, and measure whether prefetches actually overlap tool latency instead of stealing bandwidth from active decode.

Figures 2 and 3 are also useful because they separately visualize temporal underutilization and spatial contention.

TokenCake: A KV-Cache-centric Serving Framework for LLM-based Multi-Agent Applications

Authors & affiliations: Zhuohang Bian, Feiyang Wu, Zhuoran Li, Teng Ma, and Youwei Zhuo. Affiliations: Peking University, Beijing, China; Alibaba Group, Beijing, China.

Tags: LLM Serving, KV Cache Movement, Agentic AI Infrastructure

Problem: Multi-agent LLM applications create KV-cache pressure that is different from single-session serving: agents block on tool calls while holding GPU memory, while critical-path agents can lose cache residency because other agents contend for the same memory pool.

Key contributions from the authors:

  • Introduces TokenCake, an agent-aware serving framework that co-optimizes scheduling and KV-cache memory management rather than treating each request independently.
  • Adds a Temporal Scheduler that offloads idle KV caches during function calls and predictively uploads them before the agent needs to resume, hiding transfer latency where possible.
  • Adds a Spatial Scheduler that dynamically partitions GPU memory using both workflow graph structure and runtime state to protect critical-path agents; reports more than 47.06% end-to-end latency reduction and up to 16.9% higher effective GPU-memory utilization over vLLM on representative multi-agent benchmarks.

Why it matters: This is the strongest signal today because it treats KV cache as a movable, schedulable resource with workflow semantics. That is exactly where disaggregated/agentic serving becomes a network-and-memory problem instead of just a batching problem.

Key insights:

  • The paper’s core distinction is temporal versus spatial KV-cache waste: stalled agents waste HBM while waiting on tools, and active agents suffer eviction when the system lacks critical-path awareness.
  • Predictive upload only helps if the serving layer has enough workflow visibility to know when an agent is likely to resume; this argues for richer APIs between agent runtimes and inference backends.
  • Cache offload is not a free lunch: it turns GPU-memory pressure into host/device or network data movement, so the design’s real deployment boundary will be PCIe/NVLink/NIC bandwidth and prefetch accuracy.
  • The graph-aware priority metric is a useful mental model for multi-agent serving: not every token stream has equal architectural value, because some streams gate far more downstream work.

Actionable lessons: Expose workflow DAGs and tool-call state to the serving layer. For large agentic deployments, treat KV cache migration like a first-class data plane: budget transfer bandwidth, preserve critical-path cache residency, and measure whether prefetches actually overlap tool latency instead of stealing bandwidth from active decode.

Towards Traffic Modelling of Multi-Agent Systems: The Role of Coordination Topology

Authors & affiliations: Davide Lamagna, Albert Cabellos, Alberto Rodriguez-Natal, Gábor Rétvári, and Berta Serracanta. Affiliations: UPC, BarcelonaTech, Barcelona, Spain; Cisco, Barcelona, Spain; Budapest University of Technology and Economics, Budapest, Hungary.

Tags: Network Measurement, Agentic LLM Traffic, Serving Workloads

Problem: Agentic LLM systems can turn one external user request into many internally generated model calls, but classical arrival models assume traffic is mostly driven by users rather than by coordination topology.

Key contributions from the authors:

  • Measures LLM-call interarrival distributions for sequential, star, and full-mesh multi-agent topologies across 500 repeated runs per topology.
  • Builds a multi-layer measurement framework spanning application, model-serving, container, and network signals.
  • Finds that topology shapes request-arrival processes: fan-out coordination introduces structural bimodality, reasoning-phase timing is better fit by a log-normal distribution, and a Poisson/exponential null model is decisively rejected.

Why it matters: For AI clusters, this is useful because it says agent traffic is not just “more requests.” Coordination structure leaks directly into backend arrival processes, TCP byte volume, and in-flight request dynamics.

Key insights:

  • Sequential, star, and full-mesh agent coordination generate measurably different load shapes even when the external task is the same.
  • Poisson assumptions are a bad default for agentic LLM backends; fan-out and reasoning phases create correlated bursts and heavy-tailed timing components.
  • Topology is an application design knob with infrastructure consequences: changing the agent graph can change inference queueing and network traffic without changing model weights.
  • The multi-layer correlation view is a good observability pattern for future agent-serving clusters: model-level throughput and network byte volume should be analyzed on a shared timeline.

Actionable lessons: When capacity-planning agentic LLM serving, benchmark coordination topologies directly instead of feeding the backend generic request traces. Admission control and load testing should include internal call expansion, fan-out bursts, and correlated tool/LLM phases; otherwise tail latency estimates will be fantasy math with a nice dashboard.

TurboRetry: Mitigating Large-Scale QUIC Handshake Floods with Off-the-Shelf DPU Offloading

Authors & affiliations: Jiahao Wu, Heng Pan, Kai Lv, Zhenyu Li, Yanbiao Li, and Gaogang Xie. Affiliations: Institute of Computing Technology, Chinese Academy of Sciences; University of Chinese Academy of Sciences; Computer Network Information Center, Chinese Academy of Sciences, Beijing, China.

Tags: DPU/SmartNICs, Transport Security, QUIC

Problem: QUIC Retry is meant to protect servers from handshake floods, but at large attack scale the Retry path itself burns host CPU on token generation, validation, packet integrity, and connection authorization.

Key contributions from the authors:

  • Designs TurboRetry, a split host/DPU design that offloads QUIC Retry work while preserving QUIC semantics.
  • Separates stateless and stateful Retry functions between the DPU and host using an extended Retry token format and a cooperation scheme intended to reduce coordination overhead.
  • Uses on-path DPA offload for connection authorization and reports 10–20× throughput improvement over host-side Retry under evaluated handshake-flood conditions.

Why it matters: Not AI-specific, but very relevant to hyperscale edge/front-end design: it is a concrete example of moving transport-control work into the DPU without fully redesigning the protocol stack.

Key insights:

  • The interesting systems tension is deployability versus correctness: offloading Retry is easy if the DPU owns everything, harder if the host must preserve protocol state and failover semantics.
  • The extended token format is doing architectural work: it carries enough information to let the DPU handle fast-path validation without turning every packet into a host round trip.
  • For AI service front doors, handshake floods and token authorization are control-plane equivalents of incast: the attack targets expensive per-connection work, not just link bandwidth.
  • The paper is a useful DPU pattern: offload narrow, CPU-expensive, semantically bounded tasks first, then keep state synchronization explicit.

Actionable lessons: For DPU designs in AI gateways, pick offload units with clear protocol boundaries and measurable host-CPU burn. Keep host/DPU state minimal, make failover semantics explicit, and verify that the offload does not become a new availability dependency or debugging black hole.

Oasis: Hiding the Cost of Querying Parquet Files in the Datapath

Authors & affiliations: Jonas Dann, Luca Tagliavini, and Gustavo Alonso. Affiliations: ETH Zürich, Zürich, Switzerland; Apple, Zürich, Switzerland. The paper notes that Luca Tagliavini’s work was done while he was a student at ETH Zürich.

Tags: SmartNICs, Disaggregated Storage, Data Path Acceleration

Problem: Disaggregated lakehouse/database systems often spend a large fraction of query time pulling compressed Parquet data from storage and decoding it on CPUs, while storage/network bandwidth grows faster than CPU cost-performance.

Key contributions from the authors:

  • Presents Oasis, a data-processing SmartNIC that decodes Parquet column chunks directly in the network datapath as data streams from storage into the compute node.
  • Combines a hardware decoder pipeline, software abstraction layer, and DuckDB integration rather than evaluating a standalone accelerator in isolation.
  • Reports that hiding Parquet decode behind the datapath can almost double DuckDB query throughput in the best case.

Why it matters: This is adjacent rather than AI-specific, but the mechanism maps cleanly to AI infrastructure: if data must cross the fabric anyway, the NIC/datapath can become a transformation stage, not just a byte pipe.

Key insights:

  • Oasis exploits a path asymmetry: bytes already traverse the NIC, so decode can be overlapped with data movement instead of serialized after arrival.
  • The design is most compelling when CPU decode is the bottleneck and the query engine can consume decoded columns without adding new copies or synchronization stalls.
  • For AI storage paths, the analogy is checkpoint/object-store/KV-feature ingestion: datapath acceleration is useful only if it is integrated end-to-end with the consumer runtime.
  • The paper also hints at a practical SmartNIC limit: fixed-function acceleration pays when the format and access pattern are common enough to justify hardware specialization.

Actionable lessons: For AI clusters, look for repeated decode/transform work on hot storage-to-GPU or storage-to-CPU paths. If the transformation is deterministic, format-stable, and bandwidth-adjacent, evaluate NIC-side or near-storage offload—but require end-to-end runtime integration before believing microbenchmarks.

Assessing Triple Modular Redundancy for Wide-Link, Low-Latency NoC Routers: Reliability and Physical Design Challenges

Authors & affiliations: Chen Wu, Michael Rogenmoser, Luca Benini, and Angelo Garofalo. Affiliations: ETH Zürich, Zürich, Switzerland; Università di Bologna, Bologna, Italy.

Tags: Scale-up Interconnects, NoC Reliability, AI Accelerators

Problem: Modern tile-based AI/physical-AI accelerators use low-latency NoC routers with very wide links, but traditional reliability work often assumes narrower, deeper-pipelined routers and may not protect against both SEUs and SETs without large cost.

Key contributions from the authors:

  • Evaluates coarse, state-only, and full Triple Modular Redundancy for a 2-cycle-latency NoC router with 512-bit links.
  • Performs RTL-to-GDSII physical design in TSMC 7nm plus RTL- and netlist-level SEU/SET fault injection campaigns.
  • Finds full TMR eliminates observed failures across more than one million injected faults per experiment; standalone router area overhead is 7.04×, but when integrated into a full AI accelerator tile the overhead is amortized to 16.8% area and 15.2% power under GEMM, with the tile critical path unaffected.

Why it matters: For scale-up fabrics and accelerator tiles, reliability cannot stop at link BER or endpoint retry. This paper asks what it costs to harden the NoC router itself when the router is the backbone of a replicated tile fabric.

Key insights:

  • State-only hardening is insufficient when transient logic faults can still propagate through wide, low-latency datapaths.
  • The scary 7.04× router-local area overhead is misleading at the system level because the router is only one part of the tile; amortization changes the architectural trade-off.
  • Advanced nodes create enough routing capacity that full TMR may be physically feasible for selected safety-critical NoC components.
  • The paper’s lesson generalizes to scale-up reliability: protect the minimal interconnect components whose failure can deadlock or silently corrupt the whole accelerator.

Actionable lessons: When evaluating scale-up interconnect reliability, separate local component overhead from tile/system overhead. Harden routers or network interfaces that can create global hangs or SDC, then validate with fault injection at the right abstraction levels rather than relying on narrow-link intuition.
