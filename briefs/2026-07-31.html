SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

Authors & affiliations: Xuchuan Luo, Jiacheng Shen, Xin Wang, and Yangfan Zhou. Affiliations: College of Computer Science and Artificial Intelligence, Fudan University; Duke Kunshan University.

Tags: LLM Serving, KV Cache Transfer, Disaggregated Inference

Why this is the top pick: This is the cleanest AI-cluster networking signal today: it treats KV cache handoff as a network data-plane problem rather than a serving-runtime afterthought. The design is especially relevant when PD-disaggregated serving lands on commodity cloud instances whose RDMA bandwidth is far below HBM bandwidth.

Deeper explanation: The mental model is that PD-disaggregated serving creates a new distributed-systems boundary between prefill and decode. Full KV transfer treats that boundary as a bulk copy; SmartGen treats it as a bandwidth-constrained cache-coherence problem with hot entries, prompt-dependent misses, and colder state. That is the right abstraction for rented or heterogeneous GPU fleets where network bandwidth grows much more slowly than HBM capacity and context length.

  • Problem: Prefill/decode disaggregation can turn KV-cache movement into the dominant stage-transition stall, especially for self-hosted cloud GPU deployments where inter-node network bandwidth is only tens of Gbps.
  • Key contributions: Proposes importance-aware KV-cache transfer so prefill nodes push only essential cache entries instead of blindly moving the full cache.; Designs SmartGen with three paths: profile-based proactive transfer, parallel on-demand transfer for dynamic misses, and host-local swap transfer for remaining entries.; Reports up to 4.3× lower time-to-second-token than full KV transfer on evaluated Llama/Qwen-style disaggregated inference workloads.
  • Why it matters architecturally: PD disaggregation only helps if the handoff does not become the dominant critical path. Selective transfer makes the KV handoff schedulable instead of treating it as an unavoidable full-state migration.

SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

Authors & affiliations: Xuchuan Luo, Jiacheng Shen, Xin Wang, and Yangfan Zhou. Affiliations: College of Computer Science and Artificial Intelligence, Fudan University; Duke Kunshan University.

Tags: LLM Serving, KV Cache Transfer, Disaggregated Inference

Problem: Prefill/decode disaggregation can turn KV-cache movement into the dominant stage-transition stall, especially for self-hosted cloud GPU deployments where inter-node network bandwidth is only tens of Gbps.

Key contributions from the authors:

  • Proposes importance-aware KV-cache transfer so prefill nodes push only essential cache entries instead of blindly moving the full cache.
  • Designs SmartGen with three paths: profile-based proactive transfer, parallel on-demand transfer for dynamic misses, and host-local swap transfer for remaining entries.
  • Reports up to 4.3× lower time-to-second-token than full KV transfer on evaluated Llama/Qwen-style disaggregated inference workloads.

Why it matters: This is the cleanest AI-cluster networking signal today: it treats KV cache handoff as a network data-plane problem rather than a serving-runtime afterthought. The design is especially relevant when PD-disaggregated serving lands on commodity cloud instances whose RDMA bandwidth is far below HBM bandwidth.

Key insights:

  • The paper names the real bottleneck well: stage-transition stall, where the decode stage waits for cache state rather than model compute.
  • KV sparsity is useful before decode starts, not only during attention computation; transferring the “likely useful” subset early can shrink the network critical path.
  • A single static selection policy is not enough: the design separates always-important entries, prompt-dependent dynamic misses, and cold entries that can be fetched from host memory later.
  • The architecture preserves exactness by fetching missing entries on demand, so the system trades extra complexity for bandwidth relief rather than simply dropping cache state.

Actionable lessons: For PD-disaggregated serving, track TTST/transition stall separately from TTFT and decode throughput. If KV transfer is saturating fabric bandwidth, prioritize semantic/importance-aware transfer and asynchronous miss paths before adding more GPUs.

Anonymous sharing is pairwise phase-blind

Authors & affiliations: Brieuc Le Roux Tardif. Affiliations: IMT Nord Europe.

Tags: Checkpoint I/O, Shared Storage, Cluster Dynamics

Problem: “Checkpoint storms” are often described as self-reinforcing phase locking among independent training jobs sharing finite storage bandwidth or a facility-level cap; this paper asks whether that mechanism actually follows from a minimal contention model.

Key contributions from the authors:

  • Proves that for two identical jobs with write time shorter than compute time, an anonymous shared resource creates no pairwise phase coupling under storage contention, a shared cap, or both.
  • Shows that in fully overlapping N-job cases the return map has reciprocal spectrum and unit determinant, making synchrony a fixed point with expanding directions rather than a generic attractor.
  • Uses an exact event-driven simulator to show random fleets neither lock nor cluster under the minimal model, while still producing heavier burst tails than independent phases.

Why it matters: This one is not a new fabric protocol, but it is a useful sanity check for large training-cluster operations. It says: if checkpoint bursts synchronize in production, symmetric anonymous contention alone may not be the root cause; look for heterogeneity, policies, retries, barriers, scheduler coupling, or non-anonymous throttling.

Key insights:

  • The key concept is anonymity: if the resource rate depends only on how many writers are active, not which writer they are, pairwise phase attraction disappears in the identical-job model.
  • No locking does not mean no bursts; even without phase attraction, the upper tail of concurrent writers can remain heavier than an independent-phase baseline.
  • The paper explicitly scopes itself as a model result, not a claim that real fleets never synchronize.
  • The result is valuable because it falsifies a tempting simple story, which is often how operational folklore gets debugged.

Actionable lessons: When diagnosing checkpoint storms, separate “burstiness exists” from “burstiness is self-reinforcing.” Instrument job heterogeneity, coordinated launch times, checkpoint libraries, backoff/retry policy, storage QoS classes, and scheduler barriers before blaming anonymous shared bandwidth.

ProFlow: RL-Driven and Performance-Aware Proactive Flow Placement in Datacenter Networks

Authors & affiliations: Sourya Saha, Md Nurul Absur, and Saptarshi Debroy. Affiliations: City University of New York.

Tags: Datacenter Networks, Flow Placement, Congestion Management

Problem: In multi-tenant leaf/aggregation fabrics, protected flows can be degraded when competing flows co-locate on shared aggregation switches, but reactive rerouting waits until throughput has already fallen.

Key contributions from the authors:

  • Proposes ProFlow, a proactive flow-placement framework that uses distributed telemetry and offline-trained reinforcement learning to reroute protected flows before degradation is visible.
  • Models early congestion precursors such as rising competing-flow activity and queue-overflow signals rather than relying only on post-hoc throughput drops.
  • Evaluates on the FABRIC testbed and reports about 40% higher mean throughput than a reactive rerouting baseline, with reroutes initiated around 34 seconds earlier on average.

Why it matters: The useful angle is anticipatory congestion control at the placement/routing layer. For AI clusters, this maps to the same failure shape as collective or storage traffic sharing a fabric: by the time a job-level metric notices throughput loss, the critical path is already polluted.

Key insights:

  • The paper treats congestion as a temporal process with precursors, not a binary event triggered when throughput collapses.
  • The RL agent is not deciding packet scheduling directly; it decides proactive placement/reroute actions for performance-sensitive flows.
  • FABRIC-testbed evaluation makes the claim more grounded than a pure simulator, though the scale is still far from hyperscale AI pods.
  • The design depends heavily on telemetry quality: noisy or delayed queue/activity signals would directly affect lead time.

Actionable lessons: For protected AI traffic classes, build early-warning telemetry around queue growth and competing-flow structure, not only application-level bandwidth. A reroute or rail change that happens 30 seconds earlier can matter more than a cleaner reaction after degradation.

Round Trip Time: A Benign Signal or an Indirect Window into Datacenter Workloads?

Authors & affiliations: Sourya Saha, Md Nurul Absur, and Saptarshi Debroy. Affiliations: City University of New York.

Tags: Datacenter Networks, Side Channels, Multi-Tenant Fabrics

Problem: Logical isolation in multi-tenant datacenter fabrics may not hide shared congestion dynamics; an observer measuring RTT over overlapping paths might infer co-located workload behavior.

Key contributions from the authors:

  • Builds a framework for workload inference from RTT observations collected on overlapping paths in shared leaf-spine fabrics.
  • Evaluates workload-induced latency signatures on a controlled multi-site datacenter testbed.
  • Reports 73.7% run-level accuracy across all workload classes, rising to 97.3% when weak-signal workloads are excluded.

Why it matters: For AI superpods this is less about security theater and more about fabric observability leakage: if collective phases, checkpoint waves, or storage bursts are visible through RTT perturbations, tenants may infer workload phase even without packet visibility.

Key insights:

  • RTT becomes an indirect sensor for shared queueing, especially when paths overlap at spine or aggregation points.
  • Workloads with weak congestion signatures are hard to classify, which is a useful caveat: the attack depends on observable fabric coupling, not magic ML.
  • The result suggests that logical network isolation needs to be paired with congestion isolation if workload privacy matters.
  • The same signal that helps attackers is also the signal operators often use for black-box fabric diagnosis; mitigation and observability are in tension.

Actionable lessons: Treat latency perturbations as potentially sensitive telemetry. For multi-tenant AI clusters, evaluate whether tenant-visible RTT can reveal collective phases, checkpoint timing, or co-tenant job class; if so, consider stronger path/queue isolation or intentional noise only after measuring SLO impact.

InferScale: GPU-Native KV Injection for Personalized LLM Serving

Authors & affiliations: Peter Li and Prashant Pandey. Affiliations: Northeastern University, Boston, Massachusetts, USA.

Tags: LLM Serving, KV Cache, GPU-Native Retrieval

Problem: Persistent personalized context is repeatedly retrieved and injected into prompts, forcing serving engines to redo prefill work even when the underlying memory facts are reused across requests.

Key contributions from the authors:

  • Proposes retrieve-and-inject inference: precompute reusable KV state for memory facts and inject it directly into vLLM’s paged cache at serving time.
  • Introduces Chunked RoPE and Context-Window Encoding to make independently encoded memories relocatable and less context-blind.
  • Implements InferScale as a vLLM KV-connector plugin and reports nearly constant TTFT as retrieval budget grows, with 3.6–4.8× TTFT reduction versus Mem0 at k=50 in evaluated settings.

Why it matters: This is adjacent rather than fabric-first, but it is relevant because it changes what crosses the memory/serving boundary: reusable KV state becomes a first-class object. That is the same direction as disaggregated KV systems, except here the fast path is GPU-resident rather than network-transfer-heavy.

Key insights:

  • The design decouples retrieved-context size from serving-time prefill latency by moving work to an offline/maintenance path.
  • KV reuse is not trivial under RoPE; the paper’s Chunked RoPE handles the position-relocation problem by storing keys before rotation and applying serving-time positions during injection.
  • GPU-resident retrieval matters because a CPU vector store can erase some of the latency benefit even if KV injection is fast.
  • The quality trade-off is explicit: 60.3% accuracy versus 63.3% for Mem0 in the highlighted Llama3.1-8B k=50 result, buying much lower TTFT and higher throughput.

Actionable lessons: If memory-conditioned serving is on the roadmap, design KV objects as reusable, addressable serving artifacts. The system boundary should not force every retrieved fact back through text-token prefill if the cache representation is stable enough to reuse.
