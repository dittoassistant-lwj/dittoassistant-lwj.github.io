AI cluster networking & infrastructure brief

Today’s batch is heavy on serving-path infrastructure: MoE phase disaggregation, shared KV memory tiers, RDMA-backed cache movement, and GPU/CPU/SSD pipelines. The top paper is ExpertPlex because it makes MoE communication interference and expert residency part of the serving architecture, not an afterthought.

Most important paper of the day

ExpertPlex: A High-Goodput Disaggregated Serving System for MoE LLMs with Adaptive Persistent Kernels

Authors & affiliations: Bingyang Wu, Chao Jin, Zili Zhang, Xinming Wei, Yinmin Zhong, Ruidong Zhu, Chengxu Yang, Xin Jin, and Yuliang Liu. Affiliations: Peking University; Independent Researcher.

Tags: MoE Serving, Disaggregated Inference, GPU/Network Overlap

Why this is the top pick: This is the strongest signal today because it attacks the exact fault line in production MoE serving: phase isolation, expert weight residency, and MoE traffic interference are coupled. The paper is especially relevant if you care about superpod-scale inference where “just split prefill and decode” becomes too coarse once one model replica spans tens or hundreds of GPUs.

Deeper explanation: ExpertPlex’s core move is to stop treating prefill/decode disaggregation as a full-model placement problem. It observes that MoE experts dominate model memory while attention modules are comparatively small, so it shares the experts across phases and gives attention its own phase-specific allocation. That separates the memory-residency problem from the phase-isolation problem. The paper then adds adaptive persistent kernels for fine-grained decode preemption and attention-initiated MoE communication so the shared experts do not become a new interference point. The mental model: MoE serving is a coupled GPU scheduling + network traffic-shaping problem, and the right abstraction boundary is inside the layer.

  • Problem: Serving large MoE LLMs with instance-level prefill/decode disaggregation duplicates massive expert weights and allocates resources at coarse multi-GPU granularity, while GPU-partitioned colocation creates head-of-line blocking, resource bubbles, wider communication, and cross-phase network interference.
  • Key contributions: Proposes a hybrid architecture that shares MoE experts across prefill and decode while disaggregating the smaller attention modules, eliminating over 95% duplicate model weights for the evaluated MoE models. Introduces adaptive persistent kernels that schedule expert computation at tile granularity, giving urgent decode work bounded preemption without CPU intervention or kernel relaunch. Uses attention-initiated one-sided MoE communication to avoid MoE-side coordination, reduce cross-phase deadlock/interference, and overlap communication from one phase with computation from the other; reports up to 2.01× goodput over instance-level P/D disaggregation and 1.66× over Green Context-style colocation.
  • Why it matters architecturally: It gives a concrete architecture for reducing MoE replica bloat while still protecting decode latency, which is exactly the kind of trade-off that shows up in superpod-scale inference.
  • Useful diagram: Figure 3 is the key system diagram: it shows ExpertPlex’s hybrid architecture with disaggregated attention servers and shared MoE servers. Figure 4 illustrates tile-level preemption, and Figure 5 shows the cross-phase overlap enabled by attention-initiated communication.

ExpertPlex: A High-Goodput Disaggregated Serving System for MoE LLMs with Adaptive Persistent Kernels

Authors & affiliations: Bingyang Wu, Chao Jin, Zili Zhang, Xinming Wei, Yinmin Zhong, Ruidong Zhu, Chengxu Yang, Xin Jin, and Yuliang Liu. Affiliations: Peking University; Independent Researcher.

Tags: MoE Serving, Disaggregated Inference, GPU/Network Overlap

Problem: Serving large MoE LLMs with instance-level prefill/decode disaggregation duplicates massive expert weights and allocates resources at coarse multi-GPU granularity, while GPU-partitioned colocation creates head-of-line blocking, resource bubbles, wider communication, and cross-phase network interference.

Key contributions from the authors:

  • Proposes a hybrid architecture that shares MoE experts across prefill and decode while disaggregating the smaller attention modules, eliminating over 95% duplicate model weights for the evaluated MoE models.
  • Introduces adaptive persistent kernels that schedule expert computation at tile granularity, giving urgent decode work bounded preemption without CPU intervention or kernel relaunch.
  • Uses attention-initiated one-sided MoE communication to avoid MoE-side coordination, reduce cross-phase deadlock/interference, and overlap communication from one phase with computation from the other; reports up to 2.01× goodput over instance-level P/D disaggregation and 1.66× over Green Context-style colocation.

Why it matters: This is the strongest signal today because it attacks the exact fault line in production MoE serving: phase isolation, expert weight residency, and MoE traffic interference are coupled. The paper is especially relevant if you care about superpod-scale inference where “just split prefill and decode” becomes too coarse once one model replica spans tens or hundreds of GPUs.

Key insights:

  • Expert weights dominate MoE model footprint, so duplicating full replicas for prefill and decode buys isolation at a brutal memory and elasticity cost.
  • The paper treats network interference as an architectural consequence of phase placement, not as a tuning detail inside the communication library.
  • Tile-level persistent scheduling is a useful control point because decode latency sensitivity lives below the operator/layer boundary.
  • Attention/MoE separation is a neat systems cut: attention is small enough to duplicate/disaggregate, while experts are large and sparse enough to share.
  • Goodput optimization has to model placement, parallelism degree, communication/computation overlap, and tile scheduling together; optimizing any one layer in isolation leaves obvious bubbles.

Actionable lessons: For MoE serving, model the prefill/decode split at module granularity rather than instance granularity. Keep expert weight residency shared where possible, reserve low-latency decode control at tile boundaries, and explicitly route/sequence MoE traffic so prefill bursts do not collide with decode on the same expert path.

HyMCache: A KV Cache Framework for Multi-Turn LLM Serving with CXL-Hybrid Memory

Authors & affiliations: Hakbeom Jang, Inho Song, Sam H. Noh, and Jongryool Kim. Affiliations: SK hynix America; Virginia Tech.

Tags: CXL Memory, KV Cache, LLM Serving

Problem: Multi-turn and agentic LLM serving increasingly depends on reusable KV state, but HBM and host DRAM are too expensive to scale to TB-class shared context capacity. SSD-backed tiers are cheaper but need latency-aware staging to avoid turning KV reuse into an I/O bottleneck.

Key contributions from the authors:

  • Integrates CXL-hybrid memory, combining in-device DRAM with SSD-backed capacity behind a CXL interface, as a KV-cache tier for multi-turn LLM serving.
  • Exploits KV-cache access properties—read-dominant, predictable, append-only—to drive request-level prefix prefetching and opportunistic write buffering.
  • Evaluates on a real CXL-HM prototype in single-aggregator and prefill/decode-disaggregated setups; reports 3.0× over local LMCache under the same DRAM budget and 1.45× in PD-disaggregated serving, while using 16× less DRAM than a 1 TB distributed-DRAM Mooncake comparison at roughly 30% lower performance.

Why it matters: HyMCache is useful because it reframes KV reuse as a memory-tiering and data-movement problem, not just a cache-hit-rate problem. That maps directly to heterogeneous AI infrastructure: the next serving bottleneck may be how quickly the system stages shared context across CXL, SSD, RDMA/NVMe-oF, and GPU memory tiers.

Key insights:

  • The authors explicitly compare memory-centric CXL-HM and storage-centric RDMA/NVMe-oF paths, which is the right design-space axis for shared KV capacity.
  • CXL-HM’s small DRAM tier is only valuable if the runtime can predict the next KV reads; otherwise SSD capacity leaks into TTFT.
  • PD-disaggregated serving stresses the KV tier differently from single-node reuse because prefill and decode nodes create remote access and staging patterns.
  • The reported Mooncake trade-off is architecturally interesting: a flash-heavy CXL tier can buy most of the benefit with much less DRAM, but not for free.

Actionable lessons: Treat KV cache tiers like an explicit memory hierarchy. Design for request-level prefetch, write buffering, and topology-aware staging rather than assuming “remote capacity” is fungible. For disaggregated serving, measure TTFT and cache-hit behavior under realistic multi-turn reuse, not only synthetic bandwidth.

Full-Pipeline Inference Optimization for MiMo-V2.5 Series: Pushing Hybrid SWA Efficiency to the Limit

Authors & affiliations: Xiaomi MiMo Team, Anqi Liu, Aoxin Ma, Bo Chen, Bo Yang, Chen Wang, Chen Zhang, Chengda Tang, Chengwei Wang, Chiheng Lou, Depeng Yan, Fuli Luo, Gang Wang, Hailin Zhang, Jiale Sun, Kang Zhou, Rui Huang, Shaohui Liu, Shen Huang, Shijie Cao, Shuaishuai Fan, Tianling Zhou, Xiangwei Deng, Xueyang Xie, Xuli Wang, Yingchun Lai, Yu Yang, Yuan Zhang, Zhen Tang, Zhonghua Deng, and Zihan Jiang. Affiliations: Xiaomi / MiMo Team.

Tags: Production LLM Serving, RDMA Cache, Hybrid SWA/MoE

Problem: Hybrid Sliding Window Attention can reduce KV-cache storage and attention compute, but production serving still has to solve prefix matching, layerwise KV prefetch, distributed cache consistency, multimodal preprocessing, and load balancing across a Hybrid SWA + MoE + multimodal stack.

Key contributions from the authors:

  • Builds a full-pipeline inference optimization for MiMo-V2.5, including strict O(W) SWA storage, layerwise prefetching, SWA-aware prefix cache trees, and specialized placement.
  • Introduces GCache, a distributed cache infrastructure with RDMA-optimized networking, plus a KVCache-affinity router that preserves load balancing while improving cache locality.
  • Extends the optimization to multimodal inputs through GPU image preprocessing, parallel video decoding, and multimodal cache sharing.

Why it matters: This one is less of a clean research prototype and more of a production engineering map. The relevant signal is that model architecture choices—Hybrid SWA, MoE, multimodal encoders—only pay off when the serving stack co-designs cache layout, RDMA cache movement, routing, and preprocessing.

Key insights:

  • Hybrid SWA shifts the serving problem from “store all KV” to “preserve the right KV semantics across layers,” which makes cache trees more complex than vanilla prefix caching.
  • RDMA cache infrastructure matters because KV reuse becomes a distributed data-plane path, not an internal runtime detail.
  • Cache-affinity routing is a balancing act: too much locality can overload hot instances, while too little locality burns prefill compute and network/cache bandwidth.
  • Multimodal serving adds extra pipelines that compete with LLM decode/prefill for GPU and I/O resources; the paper treats these as part of the same full-pipeline problem.

Actionable lessons: When adopting attention variants such as SWA, budget engineering time for cache semantics and distributed cache movement. Keep routing aware of KV locality, but constrain it with load signals. For production systems, evaluate the entire path—decode, prefill, RDMA cache, media preprocessing—not just model-kernel speedups.

Taurus: Accelerating Out-of-Core Graph Neural Network Inference on Billion-Scale Graphs

Authors & affiliations: Pranjal Naman and Yogesh Simmhan. Affiliations: Department of Computational and Data Sciences, Indian Institute of Science (IISc), Bangalore, India.

Tags: GPU/CPU/SSD Pipeline, Out-of-Core Inference, Heterogeneous Infrastructure

Problem: Billion-scale GNN inference can exceed RAM and GPU memory. Distributed systems pay high communication and infrastructure cost, while disk-based approaches suffer random/repeated feature gathers and wasted reads.

Key contributions from the authors:

  • Reformulates layer-wise GNN inference as source-centric broadcasts over sequential SSD scans instead of random repeated gathers.
  • Builds a pipelined GPU–CPU–SSD hierarchy with topology-aware reordering, pending-message eviction, non-buffered sequential reads, GPU-backed writes, and a GPU-resident hot store for high-degree vertices.
  • Reports 7–25× speedup over the strongest layer-wise baseline and 40–140× over vertex-wise baselines on out-of-core graphs up to 269M vertices, 4B edges, and 514 GiB of features.

Why it matters: This is adjacent rather than LLM-specific, but the architecture is relevant to heterogeneous AI infrastructure. It is a concrete example of designing the I/O path around GPU work, SSD sequentiality, CPU staging, and graph topology instead of treating storage as a slow backing store.

Key insights:

  • The key trick is changing the access pattern: sequential SSD broadcasts are much friendlier than random feature gathers.
  • Topology-aware reordering is not just graph-theory polish; it changes cache/hot-store hit behavior and reduces repeated I/O.
  • A small GPU-resident store for high-degree vertices is a practical skew-handling mechanism.
  • The design echoes KV/offload systems: prefetch and tiering only work when the runtime understands future access structure.

Actionable lessons: For GPU systems that spill to SSD, design around access regularization first. Use topology/workload structure to turn random pulls into sequential streams, reserve scarce GPU memory for high-reuse items, and bypass host page cache when it becomes noise rather than help.

Useful diagram: Figure 4 is the main Taurus architecture diagram, showing sequential graph/embedding reads, tiered aggregation, and the GPU/CPU/SSD pipeline. Figure 3 clearly contrasts gather-based and broadcast-based execution.

OrderMoE: An expert similarity driven distributed edge MoE inference

Authors & affiliations: Xin Yuan, Ning Li, Quan Chen, Wenchao Xu, Athanasios V. Vasilakos, Song Guo, and Haijun Zhang. Affiliations: Harbin Institute of Technology; Guangdong University of Technology; Hong Kong University of Science and Technology; University of Agder.

Tags: Distributed MoE, Edge/Network Constraints, Communication Reduction

Problem: Distributed MoE inference over edge servers suffers because exact expert placement can force frequent cross-server token transfers over ordinary Internet links with lower bandwidth, higher latency, and more variable conditions than datacenter RDMA/InfiniBand fabrics.

Key contributions from the authors:

  • Builds an expert-similarity model from router-induced logits representations and groups same-layer experts by functional similarity.
  • Deploys representative experts across edge servers to improve local similarity coverage and reduce remote expert invocations.
  • Adds quality-aware, trajectory-aware runtime selection to decide when a token can use a local substitute expert versus when it must invoke the exact remote expert; reports lower latency, tail latency, cross-server traffic, and remote invocation ratio on a distributed edge testbed.

Why it matters: This is lower priority than the datacenter papers, but it is a useful MoE communication idea: sometimes the best way to reduce network traffic is to relax exact remote execution under a quality guardrail. That is potentially relevant to wide-area or heterogeneous inference where exact expert locality is expensive.

Key insights:

  • The paper explicitly distinguishes cloud fabrics from edge interconnects: RDMA/InfiniBand assumptions do not hold over ordinary Internet paths.
  • Expert similarity creates a new locality dimension; a server does not need every exact expert if it has a quality-feasible substitute.
  • The quality/network trade-off is token-trajectory dependent because each layer’s decision changes where the token state resides next.
  • This is approximate systems design: useful only if the quality loss is bounded and observable.

Actionable lessons: For bandwidth-limited distributed MoE, consider expert placement with substitutability, not only exact placement and replication. But keep a runtime quality gate and make the token-location transition explicit; otherwise communication savings can silently become model-quality regressions.

Useful diagram: No single architecture figure was as clearly useful from the extracted text as the previous papers; the verified front matter and introduction describe the distributed edge MoE setting and the exact-vs-substitute expert execution problem.

Fast take

Read ExpertPlex first if you want serving architecture signal. HyMCache is the best memory-tier paper because it connects CXL/SSD hardware to concrete KV reuse behavior. MiMo-V2.5 is worth skimming for production RDMA cache plumbing. Taurus and OrderMoE are adjacent, but useful for heterogeneous I/O and communication-reduction patterns.
