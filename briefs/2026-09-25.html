AI cluster networking & infrastructure brief

Today’s strongest theme is dynamic control for shared inference clusters: elastic prefill/decode boundaries, serving-aware KV movement into CXL storage, network-contention-aware training simulation, and finer-grained GPU isolation for agentic kernel search.

Most important paper of the day

Crossflow: Prefill-Decode Elasticity for Agentic LLM Serving

Authors & affiliations: Yi Xu, Ehsan K. Ardestani, Wenyin Fu, Martin Schatz, Krishna Malladi, Zhan Shu, Adnan Aziz, Shobhit Kanaujia, Ajit Mathews, Chunqiang Tang — Meta Platforms.

Tags: LLM Serving, Prefill/Decode Disaggregation, Cluster Capacity Control

Why this is the top pick: This is the strongest signal today because it treats LLM serving as a dynamic cluster-control problem, not a fixed prefill/decode partitioning exercise. The key idea is practical: keep node roles stable, but temporarily lend bounded local-prefill capacity across the phase boundary when workload shape shifts.

Deeper explanation: Crossflow attacks a real operational mismatch in P/D-disaggregated serving: phase-specialized pools are efficient only while their demand ratio is stable. The paper’s lease mechanism gives decode nodes a bounded way to absorb prefill bursts without role conversion, permanent repartitioning, or blindly adding hardware. For Ethan’s world, this is interesting because it pushes inference control closer to transport-style admission: capacity is advertised, borrowed, revoked, and guarded by explicit resource envelopes.

  • Problem: Prefill-decode disaggregation improves LLM serving efficiency, but its static pool boundary cannot track fast swings in prefill versus decode demand from chat and agentic workloads. Reassigning replicas can take tens of minutes, so fixed sizing either strands GPUs or creates queueing.
  • Key contributions:
  • Characterizes phase-demand volatility: uncached-input/output token ratios show peak-to-mean ratios up to 4.7× at minute timescales, and public agentic traces span a median 24.5× hourly ratio within a day.
  • Introduces Crossflow, where decode nodes expose short-lived, revocable local-prefill leases bounded by compute, KV capacity, transfer work, and projected output.
  • Adds shape-aware admission and spill selection so borrowed prefill work stays within SLO-safe envelopes; reports 16.2–17.4% geometric-mean token-throughput gains over static P/D, and up to 43.4% at high load.
  • Why it matters architecturally: Static cluster partitions are a poor fit for agentic traffic. Crossflow’s leases make phase elasticity a runtime primitive while preserving isolation between the long-lived prefill/decode roles.

Crossflow: Prefill-Decode Elasticity for Agentic LLM Serving

Authors & affiliations: Yi Xu, Ehsan K. Ardestani, Wenyin Fu, Martin Schatz, Krishna Malladi, Zhan Shu, Adnan Aziz, Shobhit Kanaujia, Ajit Mathews, Chunqiang Tang — Meta Platforms.

Tags: LLM Serving, Prefill/Decode Disaggregation, Cluster Capacity Control

Problem: Prefill-decode disaggregation improves LLM serving efficiency, but its static pool boundary cannot track fast swings in prefill versus decode demand from chat and agentic workloads. Reassigning replicas can take tens of minutes, so fixed sizing either strands GPUs or creates queueing.

Key contributions from the authors:

  • Characterizes phase-demand volatility: uncached-input/output token ratios show peak-to-mean ratios up to 4.7× at minute timescales, and public agentic traces span a median 24.5× hourly ratio within a day.
  • Introduces Crossflow, where decode nodes expose short-lived, revocable local-prefill leases bounded by compute, KV capacity, transfer work, and projected output.
  • Adds shape-aware admission and spill selection so borrowed prefill work stays within SLO-safe envelopes; reports 16.2–17.4% geometric-mean token-throughput gains over static P/D, and up to 43.4% at high load.

Why it matters: This is the strongest signal today because it treats LLM serving as a dynamic cluster-control problem, not a fixed prefill/decode partitioning exercise. The key idea is practical: keep node roles stable, but temporarily lend bounded local-prefill capacity across the phase boundary when workload shape shifts.

Key insights:

  • The P/D split is not wrong; the static boundary is the brittle part. Agentic traffic makes the prefill/decode ratio move faster than replica repartitioning can react.
  • Leases are a clean safety abstraction: they let decode nodes advertise borrowable prefill capacity without permanently becoming prefill nodes or violating local KV/compute budgets.
  • Demand shape matters as much as volume. The policy must reason about prompt size, expected output, transfer cost, and decode pressure before admitting spillover work.
  • The result points toward inference fabrics where capacity control, KV movement, and SLO admission are coupled in one control loop.

Actionable lessons: For disaggregated serving, instrument the prefill/decode demand ratio at minute granularity and model it as a control signal. Avoid treating pool sizes as static knobs; expose revocable capacity leases with explicit compute, KV, network-transfer, and output-token budgets.

verified arXiv paper · CXL-SSD, KV Cache, Heterogeneous Memory

Bridging LLM Serving and CXL-SSDs with Chunk-Aware KV Cache Management

Authors & affiliations: Hyunsun Chung, Taewan Noh, Minji Kim, Joo-Young Hwang, Hong-Yeon Kim, Youngjae Kim — Sogang University; Samsung Electronics Co.; ETRI.

Tags: CXL-SSD, KV Cache, Heterogeneous Memory

Problem: NAND-backed storage has the capacity for large prefix/KV caches, but block I/O adds CPU cache contention, host-DRAM staging, and NAND latency. A stock CXL-SSD is byte-addressable but still not enough without serving-aware KV semantics and prefetch coordination.

Key contributions from the authors:

  • Characterizes why block-based SSD retrieval hurts TTFT: CPU cache contention, forced host-DRAM staging, and NAND latency persist even when the backing medium is replaced by DRAM.
  • Proposes LM-CXD, a CXL-SSD design that makes KV chunks visible to the device, exposes NAND-to-DRAM progress to the serving engine, and uses device DRAM as a GPU-accessible buffer.
  • Coordinates request scheduling with windowed/layerwise prefetching, reducing average TTFT versus stock CXL-SSD by up to 2.6× with compute-asynchronous prefetching and 4.03× with layerwise prefetching.

Why it matters: This is a good heterogeneous-infrastructure paper because it does not just say “put KV on CXL.” It shows that the interface boundary is the real problem: the serving engine knows future KV chunk demand, while the device controls placement and movement.

Key insights:

  • Byte addressability alone does not make storage a useful KV-cache tier; the device needs semantic visibility into chunks, layers, and prefetch windows.
  • The serving path pays for block-interface artifacts even when NAND is removed, so optimizing only media latency misses a large part of TTFT.
  • Device DRAM becomes a staging/cache layer that should be scheduled jointly with GPU compute and request admission.
  • The paper is essentially a contract proposal between vLLM-like engines and CXL storage devices: expose enough intent for the device to prefetch the right KV at the right layer.

Actionable lessons: When designing KV-cache tiers, define explicit chunk semantics and progress visibility across the engine/device boundary. Evaluate TTFT, ITL, host cache interference, and staging-copy cost separately; otherwise “fast storage” can look fine in bandwidth tests and still fail on serving latency.

verified arXiv paper · GPU Cluster Simulation, Network Contention, Distributed Training

Accurate Simulation of Distributed Training Jobs with Network Contention Modeling

Authors & affiliations: Yeonho Yoo, Hyunho Lee, Hyunmok Choi, Chuck Yoo, Gyeongsik Yang — Department of Computer Science and Artificial Intelligence, Dongguk University; Department of Computer Science and Engineering, Korea University.

Tags: GPU Cluster Simulation, Network Contention, Distributed Training

Problem: Trace-driven GPU-cluster simulators often ignore network contention or use a fixed slowdown. That misses the fact that placement decisions determine which jobs share server NICs and inter-server links, changing iteration time and JCT.

Key contributions from the authors:

  • Introduces MoSim, a trace-driven simulator that augments jobs with compute time, networking time, and networking volume from GPU-free characterization.
  • Models dynamic NIC and inter-server-link contention based on the current worker assignment instead of applying a static penalty.
  • Reports large fidelity improvements: up to 3.28× lower average-JCT error, 7.79× lower P99-JCT error, 8.48× lower makespan error, and 8.63% average error in NIC contention factors.

Why it matters: This is directly relevant to AI cluster scheduling research. If the simulator’s network model is wrong, scheduler conclusions about placement, consolidation, and sharing policies can be confidently wrong.

Key insights:

  • Network contention is placement-dependent state, not a workload constant. The same job can have different networking time depending on co-running jobs and path sharing.
  • Small and medium jobs are especially important because schedulers have many placement choices, and those choices alter NIC/link sharing.
  • GPU-free characterization is a pragmatic way to lower profiling cost while still retaining per-job communication volume and compute/network split.
  • The paper makes a useful measurement point: fixed-contention factors can produce large JCT errors even if they look plausible on average.

Actionable lessons: For cluster-scheduler experiments, require the simulator to expose per-job network volume, NIC sharing, and link contention. Treat contention modeling as part of the validity contract, not a calibration afterthought.

verified arXiv paper · GPU Infrastructure, Kernel Benchmarking, Multi-Tenant Isolation

KREX: Concurrent Kernel Benchmarking on Shared GPUs via Region-Granular Exclusivity

Authors & affiliations: Tianyu Feng, Haoxuan Yu, Tianyuan Wu, Lingyun Yang, Daocheng Ying, Yuxiao Wang, Ruibo Fan, Yinghao Yu, Guodong Yang, Liping Zhang, Wei Wang — HKUST, Hong Kong SAR, China; Alibaba Group, China.

Tags: GPU Infrastructure, Kernel Benchmarking, Multi-Tenant Isolation

Problem: LLM agents for kernel optimization need faithful timing measurements on real GPUs. Reserving a GPU for a whole session or command preserves fidelity but wastes capacity because only a small timed region actually needs exclusivity.

Key contributions from the authors:

  • Introduces region-granular exclusivity: agents mark timing-sensitive regions, and KREX enforces exclusivity only there while allowing concurrency elsewhere.
  • Blocks competing GPU submissions, drains outstanding work, freezes sibling processes, and isolates CPU cores during marked timing regions.
  • Uses persistent context processes to reduce repeated GPU context-creation overhead; reports up to 3.4× benchmarking throughput with negligible p95 timing inflation for kernels above 0.1–10 ms.

Why it matters: This is not a networking paper, but it is a useful AI-infra signal: agentic kernel search is becoming its own GPU fleet workload, and its measurement path needs isolation semantics that are finer than “give every agent a whole GPU.”

Key insights:

  • The scarce resource is not just GPU time; it is uncontended, measurement-valid GPU time. That distinction enables much higher sharing.
  • CPU-side driver threads matter for timing fidelity, so isolation has to cover host execution around the GPU submissions, not only the device queue.
  • Persistent context processes attack a hidden scalability issue: context creation can serialize node-wide and erase the benefits of fine-grained sharing.
  • The design pattern generalizes to other benchmarking/profiling workloads: reserve exclusivity around semantic critical sections, not around the whole job.

Actionable lessons: For internal GPU benchmarking platforms, annotate timing-critical regions explicitly and isolate at that granularity. Track measurement inflation distributions, not just throughput, because small bias can mislead automated search loops.

verified arXiv paper · LLM Serving, Autoscaling, Shared GPU Clusters

Cross-Model Autoscaling for Shared LLM Serving

Authors & affiliations: Xin Zhang, Xianyan Xie, Zhen He, Xijin Yin, Xingtong Lin, Bangbo Liang, Zequn Cheng, Peihao Huang, Guo Chen — Hunan University.

Tags: LLM Serving, Autoscaling, Shared GPU Clusters

Problem: Shared MaaS clusters host multiple LLMs under one GPU budget. Model-local autoscalers can detect pressure, but they cannot decide which model should receive capacity when every model competes for the same full GPU pool.

Key contributions from the authors:

  • Defines Token Service Share (TSS), a calibrated, demand-normalized signal for comparing service health across heterogeneous models and SLO classes.
  • Builds TRE, a control-plane framework that separates fast rescue from slower rebalancing and moves routable capacity through bounded receiver–donor transitions.
  • Implements TRE on Kubernetes hot-switch serving without changing the inference scheduler, reporting 11.9–79.0% P95 and 12.5–72.6% P99 end-to-end latency reductions versus a KV-cache-pressure autoscaler across seven traces.

Why it matters: This is the control-plane sibling to Crossflow. It says raw queue length, cache pressure, and throughput are not comparable across models; shared serving needs a normalized service-deficit signal before it can arbitrate scarce GPUs.

Key insights:

  • Autoscaling under a fixed budget is a reallocation problem, not a scale-out problem. Every receiver needs an eligible donor.
  • Local pressure metrics can be non-monotonic relative to SLO health, which makes them dangerous as cross-model arbitration signals.
  • The fast/slow control split is useful: rescue handles urgent deficits, while rebalancing dampens oscillations.
  • Hot-switching only helps if the controller can decide where capacity should move; actuation speed and signal quality are both required.

Actionable lessons: For multi-model serving fleets, build a comparable health metric before tuning the autoscaler. Explicitly model donor safety, release guards, and SLO-class normalization; otherwise “scale model X” can silently harm a more critical model Y.
