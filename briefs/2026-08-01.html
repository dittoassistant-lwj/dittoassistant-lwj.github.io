NELSSA: A GPU-PNM Heterogeneous System for Mixed-Length LLM Serving via Length-based Request Placement

Authors & affiliations: Sookyung Choi, Seungyong Lee, Kangkyu Park, Yunseo Chun, Junseok Lee, Hyeongseok Gwak, Myunghyun Rhee, Euiseok Kim, Donguk Moon, Kwangsik Shin, Guseul Heo, Youngpyo Joo, Hoshik Kim, and Jongse Park. Affiliations: SK hynix, Republic of Korea; KAIST, Republic of Korea.

Tags: LLM Serving, CXL/RDMA, Heterogeneous AI Infrastructure

Why this is the top pick: This is the most infrastructure-heavy signal today: it makes long-context serving a cross-tier placement and data-movement problem, not just a kernel optimization problem.

Deeper explanation: NELSSA is interesting because it treats heterogeneous hardware as a serving-time scheduling surface. The core move is to keep short-context decode on GPUs, where tensor-core throughput and batching are valuable, while routing long-context attention state toward a PNM tier backed by CXL-era disaggregation. That gives the runtime a way to avoid the classic failure mode where a few huge contexts consume HBM, shrink the active batch, and inflate tail latency for everyone else. The design is also network-facing: RPC/RDMA and cross-tier memory movement are part of the critical path, so the paper is really about coordinating placement, migration, and attention execution across a heterogeneous fabric.

  • Problem: Mixed-length LLM serving mixes short prompts with 100K+ token contexts, causing GPU-only serving to lose batching efficiency and hit HBM pressure just when long-context agent workloads need stable latency.
  • Key contributions: Introduces NELSSA, an end-to-end GPU plus Processing-near-Memory serving system for mixed-length workloads.; Uses length-based placement: short-context requests run on GPUs, long-context requests move to the PNM tier, with background migration when requests grow.; Implements sparse attention on real PNM devices and a host runtime that moves state across a CXL-enabled infrastructure with RPC and RDMA support; reports up to 5.5× decode-throughput gain and up to 15× lower P99 latency versus GPU-only baselines.
  • Why it matters architecturally: Heterogeneous serving only works if the runtime knows when to move state, where attention should execute, and how much cross-tier bandwidth the movement consumes.

NELSSA: A GPU-PNM Heterogeneous System for Mixed-Length LLM Serving via Length-based Request Placement

Authors & affiliations: Sookyung Choi, Seungyong Lee, Kangkyu Park, Yunseo Chun, Junseok Lee, Hyeongseok Gwak, Myunghyun Rhee, Euiseok Kim, Donguk Moon, Kwangsik Shin, Guseul Heo, Youngpyo Joo, Hoshik Kim, and Jongse Park. Affiliations: SK hynix, Republic of Korea; KAIST, Republic of Korea.

Tags: LLM Serving, CXL/RDMA, Heterogeneous AI Infrastructure

Problem: Mixed-length LLM serving mixes short prompts with 100K+ token contexts, causing GPU-only serving to lose batching efficiency and hit HBM pressure just when long-context agent workloads need stable latency.

Key contributions from the authors:

  • Introduces NELSSA, an end-to-end GPU plus Processing-near-Memory serving system for mixed-length workloads.
  • Uses length-based placement: short-context requests run on GPUs, long-context requests move to the PNM tier, with background migration when requests grow.
  • Implements sparse attention on real PNM devices and a host runtime that moves state across a CXL-enabled infrastructure with RPC and RDMA support; reports up to 5.5× decode-throughput gain and up to 15× lower P99 latency versus GPU-only baselines.

Why it matters: This is the most infrastructure-heavy signal today: it makes long-context serving a cross-tier placement and data-movement problem, not just a kernel optimization problem.

Key insights:

  • Long requests are not merely “bigger batches”; they can poison the batch shape for short requests by consuming HBM and collapsing GPU running batch size.
  • The system separates compute that wants tensor cores from attention state that mostly wants capacity and bandwidth, then routes by sequence length.
  • Runtime migration matters because request length is not always known up front; architecture has to support growth without recomputing the whole prefix.
  • The CXL/RDMA path is not decorative: it is the substrate that makes GPU-PNM memory movement a serving-runtime primitive.

Actionable lessons: For heterogeneous AI pods, treat sequence length as a placement dimension alongside model size and SLO class. If long-context tails are starving short decode batches, consider tiering KV-heavy attention state rather than scaling GPU memory blindly. Instrument migration overhead and cross-tier bandwidth as first-class serving metrics.

DualDecoder: Accelerate Long Context LLM Inference by Predictive Prefetch

Authors & affiliations: Zuning Liang, Zhiyi Yao, Qi Chen, Yuedong Xu, Hao Dai, Zhiqiang Ding, Tongkai Yang, Jinlong Hou, and Yuan Cheng. Affiliations: Fudan University; Shanghai Innovation Institute; Ant Group, China.

Tags: LLM Serving, KV Cache, Host-GPU Data Movement

Problem: Sparse KV-cache systems offload most long-context KV entries to host memory, but the metadata and auxiliary state needed to decide what to retrieve can itself become a GPU-memory bottleneck at high concurrency.

Key contributions from the authors:

  • Shows that sparse-KV auxiliary state can dominate GPU memory residency, reducing maximum request batch size.
  • Proposes DualDecoder, using a dual-token pipeline where the preceding speculated token predicts the critical KV entries for the next decode step.
  • Adds layer-aware KV transfer scheduling and a layer-scoped memory manager; reports up to 2.62× decoding-throughput improvement over evaluated state-of-the-art systems while preserving latency and quality.

Why it matters: This attacks a very practical long-context bottleneck: once KV lives off GPU, the serving system becomes a prefetching and transfer-scheduling engine.

Key insights:

  • The useful trick is predictive overlap: identify likely next-step KV before it is needed, then hide host-to-GPU transfer under layer compute.
  • Auxiliary metadata is a real resource, not bookkeeping dust; in long-context serving it can consume enough GPU memory to cap concurrency.
  • Layer-aware scheduling turns KV retrieval into a pipeline, which is closer to storage/network prefetching than normal attention optimization.
  • Miss handling needs priority, otherwise the tail latency benefit can be erased by late KV transfers.

Actionable lessons: When designing KV offload, measure auxiliary-state residency separately from KV residency. Optimize for overlap windows and per-layer buffer lifetimes, not just average retrieval bandwidth. The right abstraction is closer to a cache prefetcher with SLO-aware miss service than a static sparse-attention kernel.

KAP: Bridging the Knowledge Selection-Runtime Consumption Gap in LLM Systems

Authors & affiliations: Shuo Wang, Fang Xi, Wenyuan Huang, Qing Wang, and Junming Su. Affiliations: QiYuanLab, Beijing, China; the PDF also lists a University of Science and Technology Beijing student email, but per-author affiliations beyond QiYuanLab are not clearly separated.

Tags: LLM Serving, KV Access Planning, Long-Context Runtime

Problem: RAG and graph-based knowledge-selection systems produce structured priors, but today’s serving backends flatten those priors into tokens and then consume the full KV state uniformly during decode.

Key contributions from the authors:

  • Defines the Knowledge Selection–Runtime Consumption gap: logical prompts preserve semantics, but physical KV access ignores upstream evidence ranking, graph topology, spans, and confidence.
  • Introduces Knowledge Access Planning, with a runtime access-plan IR that governs physical KV access without changing model weights, training, or logical prompt semantics.
  • Instantiates the idea with GraphSpec and reports comparable answer quality while reducing proposal-time KV access to 5.5% of source KV state at 128K context.

Why it matters: This is less fabric-facing than NELSSA, but the systems idea is sharp: serving runtimes should consume context according to structured access plans, not just token position.

Key insights:

  • The paper cleanly separates logical context semantics from physical KV consumption, which is the right mental model for long-context serving efficiency.
  • A runtime access plan could become a scheduling/control surface for KV movement, placement, and prefetching across GPU, CPU, and remote memory tiers.
  • The fallback/verification path is important because selective KV access must preserve answer quality, not just reduce bytes touched.
  • If GraphRAG-style systems already know which evidence matters, discarding that information before decode is wasteful infrastructure design.

Actionable lessons: Expose structured retrieval metadata to the serving backend instead of serializing it away. For AI infrastructure, a “KV access plan” could become a contract between the RAG layer, cache manager, and data-movement layer. The research risk is correctness: plan-guided access needs robust fallback when the selector is wrong.

SemPIC: Learning Semantic Position-Independent KV Caches

Authors & affiliations: Hui Xie, Peng Xiao, Yutong Deng, Shuoran Dou, Jian Yang, and Jinyang Guo. Affiliations: School of Computer Science and Engineering, Beihang University; Institute of Artificial Intelligence, Beihang University; Shen Yuan Honors College, Beihang University; State Key Laboratory of Complex & Critical Software Environment.

Tags: KV Cache Reuse, LLM Serving, Position-Independent Cache

Problem: Prefix caching cannot reuse the same document when it appears under different instructions, histories, or document order, while naïvely relocating precomputed KV states fails because isolated document KVs lack future request context.

Key contributions from the authors:

  • Diagnoses why position-independent cache reuse breaks: boundary-conditioned fixes reduce near-boundary error but leave interior and task-level residuals.
  • Trains a LoRA-enabled Writer to compile native per-layer document KVs offline while keeping the pretrained decoder as an unchanged Reader.
  • Introduces KV Gradient Checkpointing for training through cached KVs and reports mean micro-F1 improving from 0.53 for KV Packet to 0.60, close to 0.62 for Full Recompute.

Why it matters: This is relevant because reusable KV objects are becoming infrastructure artifacts. If they can be moved, composed, and reused safely, the serving system can avoid repeated prefill and reduce data movement.

Key insights:

  • Position correction is not enough; semantic/contextual completeness of the cached document state is the harder problem.
  • The Writer/Reader split keeps the online serving interface mostly standard, pushing adaptation cost into offline cache construction.
  • The result suggests future cache tiers may store learned, semantically reusable KV blocks rather than raw prompt-derived state.
  • The design is a quality/efficiency tradeoff: it approaches full recompute but does not exactly match it across all tasks.

Actionable lessons: If building a distributed KV cache, do not assume KV blocks are freely relocatable after RoPE adjustment. Track the conditions under which a cache object was constructed, and consider offline adaptation/validation for reusable documents before treating them as portable serving state.

Useful diagram: Figure 2 is the key system diagram: it shows the Writer compiling document KVs through the native KV interface while the Reader stays unchanged. Figure 1 maps SemPIC against other position-independent cache designs.

LongStraw: Long-Context RL Beyond 2M Tokens under a Fixed GPU Budget

Authors & affiliations: Changhai Zhou, Kieran Liu, Yuhua Zhou, Qian Qiao, Jun Gao, Harry Zhang, Irvine Lu, Nolan Ho, Lucian Li, Andrew Lei, Cleon Cheng, Steven Chiang, Yihang Zeng, Di Zhang, Rio Yang, Kaijie Chen, Andrew Chen, Pony Ma, Weizhong Zhang, and Cheng Jin. Affiliations: MindLab; Fudan University.

Tags: Distributed Training, Long-Context RL, Communication/State Management

Problem: Million-token RL post-training is limited by live state lifetime and distributed ownership: GRPO keeps prompt graphs, response graphs, model state, caches, and communication buffers live far too long under conventional autograd.

Key contributions from the authors:

  • Introduces an objective-aware transaction that captures shared prompt state without autograd, replays one policy response at a time with autograd, and accumulates gradients before one distributed finalization.
  • Specializes the transaction for two very different model structures, including CP-sharded KV/latent pages, cross-rank composition, and EP32 routed-token dispatch.
  • Demonstrates exact-attention response-only steps beyond 2M positions on eight H20 GPUs and a full exact-2M online GRPO workflow on 32 H20 GPUs.

Why it matters: This is not a network paper in the narrow sense, but it is valuable for Ethan because it exposes how context parallelism, expert parallelism, cache ownership, and distributed gradient finalization define the real training capacity boundary.

Key insights:

  • The bottleneck is resident-state lifetime, not only attention FLOPs; this is the same shape as many cluster-scale memory/network problems.
  • Response replay trades time for memory, but it also changes when collectives and cross-rank state composition occur.
  • The paper’s GLM path is a useful case study in CP32 plus EP32 ownership and routed-token movement under long-context RL.
  • Sampler-to-trainer handoff is part of the system: vLLM generation and Megatron training share position configuration and adapter state.

Actionable lessons: For long-context RL systems, design the state transaction before optimizing kernels. Make page ownership, cross-rank merge points, expert dispatch, and final gradient synchronization explicit; otherwise memory capacity and communication buffers silently set the maximum context length.
